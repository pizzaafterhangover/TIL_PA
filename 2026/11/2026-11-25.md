#### ROS2 Software 준비

##### 진단
```bash

```
>RAM은 3.7GB입니다. 이 상태로 cartographer를 빌드하면 거의 확실히 OOM으로 죽을듯.

##### ROS 2 저장소 등록

```bash
sudo apt update && sudo apt install -y software-properties-common curl
sudo add-apt-repository -y universe

export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F\" '{print $4}')
echo "$ROS_APT_SOURCE_VERSION"
```

echo 결과가 비어 있으면 여기서 멈추고 알려주세요. 원인은 GitHub API 제한이나 네트워크 문제입니다. 버전(예: 1.x.x)이 나오면 계속 진행합니다.
```bash
curl -fL -o /tmp/ros2-apt-source.deb \
  "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.resolute_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb
sudo apt update
```
curl이 404로 실패하면 해당 릴리스에 resolute용 .deb가 없다는 뜻입니다. 그 출력을 붙여주시면 다른 방법으로 우회할게요.

##### Swap 2GB 만들기 (지금 0B라 필수)
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

cartographer 빌드까지 생각하면 4GB(-l 4G)가 더 안전합니다. 대신 SD카드 여유 공간을 그만큼 씁니다. 여유 공간은 df -h /로 확인할 수 있어요.

##### apt에 있는 패키지 확인 (Pi)

포팅 소스의 package.xml 의존성에서 뽑은 목록입니다.
```bash

for p in hls-lfcd-lds-driver xacro robot-state-publisher realsense2-description realsense2-camera \
         pcl-conversions cartographer cartographer-ros-msgs camera-ros v4l2-camera; do
  printf "%-28s %s\n" "$p" "$(apt-cache policy ros-lyrical-$p | awk '/Candidate/{print $2}')"
done
```
(none)이나 빈칸으로 나오는 패키지는 소스 빌드 대상입니다.

**pcl-conversions** 를 특히 보세요. PC(24.04)에서 소스 빌드했던 이유는 PCL 1.15가 없었기 때문이에요. 26.04에는 1.15가 있을 가능성이 높아서, Pi에서는 apt로 해결되면 소스 빌드가 하나 줄어듭니다.

**realsense2-description**은 꼭 필요합니다. 포팅된 turtlebot3_description이 의존하고 있어요. 노트상 카메라가 Pi 카메라가 아니라 D435라서 그렇습니다.

##### SBC에 필요 없는 패키지 제거 (Pi)
두 package는 raspberry에서 동작시키기에 너무 크다고 판단되어 제외, cloud(or hostpc)에서 동작시킬 예정
```bash
rm -rf ~/turtlebot3_ws/src/turtlebot3/turtlebot3_navigation2
rm -rf ~/turtlebot3_ws/src/turtlebot3/turtlebot3_cartographer
rm -rf ~/turtlebot3_ws/src/turtlebot3/turtlebot3
```

마지막 turtlebot3는 상위 폴더가 아니라 그 안에 있는 메타패키지입니다. 이 메타패키지는 cartographer와 navigation2를 의존성으로 갖고 있어서, 남겨두면 rosdep이 없는 패키지를 찾다가 에러를 냅니다. 빈 껍데기 패키지라 지워도 기능에는 영향이 없어요.

##### 의존성 설치 (Pi)
```bash
source /opt/ros/lyrical/setup.bash
sudo rosdep init        # 처음 한 번만. "already exists" 에러가 나면 무시
rosdep update
cd ~/turtlebot3_ws
rosdep install --from-paths src --ignore-src -r -y --rosdistro lyrical
```
마지막에 All required rosdeps installed successfully가 나와야 합니다. ERROR: ... Cannot locate rosdep definition이 나오면 그 출력으로 문제를 해결해야 합니다.

##### 빌드 (Pi)
```bash
cd ~/turtlebot3_ws
source /opt/ros/lyrical/setup.bash
MAKEFLAGS=-j2 colcon build --symlink-install --parallel-workers 1 2>&1 | tee build.log
```
MAKEFLAGS=-j2는 RAM 3.7GB에서 메모리 부족(OOM) 없이 빌드하기 위한 설정이에요. 그래도 빌드가 중간에 멈추거나 killed 메시지가 나오면 -j1로 낮추세요.

확인:
```bash
grep -c -i "warning" build.log
source install/setup.bash
ros2 pkg list | grep -E "turtlebot3|coin_d4|dynamixel"
```
Summary: N packages finished에 실패 항목이 없으면 성공입니다. 경고 개수도 같이 알려주세요. 포팅 TODO에 "SBC 26.04 툴체인에서 경고 재확인" 항목이 남아 있어서 그 결과로 체크할 수 있어요.

##### udev 규칙 적용 (Pi)
```bash
sudo cp ~/turtlebot3_ws/src/turtlebot3/turtlebot3_bringup/script/99-turtlebot3-cdc.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```


이 규칙 파일은 OpenCR 장치 권한만 다루는 게 아닙니다. LDS-03(CP2102, 10c4:ea60)을 꽂으면 /dev/tb3_lidar라는 고정 이름도 만들어줘요. coin_d4_driver의 설정 파일(params/single_lidar_node.yaml)이 바로 이 /dev/tb3_lidar를 포트로 쓰기 때문에 이 단계를 빼면 라이다가 연결되지 않습니다.

확인 (OpenCR과 LDS-03을 USB로 연결한 상태에서):
```bash
ls -l /dev/ttyACM0 /dev/tb3_lidar
```
둘 다 보이면 성공입니다. /dev/tb3_lidar가 없다면 lsusb | grep -i 10c4로 라이다가 인식되는지 확인해 주세요.

#### OpenCR 셋팅
##### OpenCR 펌웨어 업로드

- Pi 
현재 설정 확인과 백업 (Pi)
```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources ~/ubuntu.sources.bak
grep -n "Types\|URIs\|Architectures" /etc/apt/sources.list.d/ubuntu.sources
```
Architectures: 줄이 이미 있으면 2번은 하지 말고 그 출력을 붙여주세요. 없는 게 일반적입니다.

##### 기존 Ubuntu 서버는 arm64만 받도록 제한 (Pi)
```bash
sudo sed -i '/^Types:/a Architectures: arm64' /etc/apt/sources.list.d/ubuntu.sources
grep -n "Types\|Architectures" /etc/apt/sources.list.d/ubuntu.sources
```
Types: 줄마다 바로 아래에 Architectures: arm64가 한 줄씩 붙어 있으면 성공입니다. 이렇게 해야 archive.ubuntu.com에서 armhf를 찾다가 404가 나는 일이 없어져요.

##### armhf 전용 소스 추가 (Pi)
```bash
sudo tee /etc/apt/sources.list.d/ubuntu-ports-armhf.sources << 'EOF'
Types: deb
URIs: http://ports.ubuntu.com/ubuntu-ports/
Suites: resolute resolute-updates resolute-security
Components: main
Architectures: armhf
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF
```
main 컴포넌트만 넣었어요. libc6가 거기 있고, 받아야 할 목록이 작을수록 apt update도 빨라집니다.

##### 소스코드 빌드 및 업로드
```bash
sudo dpkg --add-architecture armhf
sudo apt update && sudo apt install -y libc6:armhf

export OPENCR_PORT=/dev/ttyACM0
export OPENCR_MODEL=turtlebot3_manipulation
rm -rf ./opencr_update.tar.bz2
wget https://github.com/ROBOTIS-GIT/OpenCR-Binaries/raw/master/turtlebot3/ROS2/latest/opencr_update.tar.bz2
tar -xvf opencr_update.tar.bz2
cd ./opencr_update
./update.sh $OPENCR_PORT $OPENCR_MODEL.opencr
```
armhf 설치가 필요한 이유는 업로드 도구 opencr_ld_shell_arm이 32비트 ARM 프로그램이라서 그래요. 이게 없으면 64비트 Pi에서 실행하는 순간 No such file or directory라는 헷갈리는 에러가 납니다.

업로드 중에는 OpenCR USB를 뽑거나 전원을 끄지 마세요. 중간에 끊기면 부트로더 모드로 다시 업로드해야 합니다.
