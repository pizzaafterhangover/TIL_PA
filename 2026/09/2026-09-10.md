# 2026-09-10 TIL — AWS 기초: 리전·IAM·크레딧

> AWS를 처음 다루며 리전 선택이 왜 중요한지, IAM으로 권한을 어떻게 나누는지, 그리고 개인·스타트업이 크레딧을 받을 수 있는 경로를 정리했다.

---

## 1. 리전

- 서버가 미국에 있으면 한국 이용자는 지연 때문에 불편을 느낀다. 사용자 위치에 맞춰 리전을 골라야 한다.
- 글로벌 서비스라면 광케이블 위치상 일본 리전이 유리하다.
- 국제 정세·환율 등 상황도 함께 따져야 한다. 분쟁 지역 등은 피하는 게 좋다.
- AWS 최신 기술은 보통 일본과 미국에 먼저 적용되는 편이다.
- 예시로 위성 안테나 대여 서비스 같은 것도 있다.
- **가입할 때 리전이 어디로 설정되는지 꼭 확인해야 한다.**

## 2. 계정과 IAM

- **IAM 계정**: 세부 권한을 나눈 계정. root 계정은 되도록 쓰지 않는 편이 좋다.
- 설정 가능한 계정 정책이 2만 개에 달할 만큼 세분화되어 있다.
- 이중 로그인(MFA)은 필수로 둔다.

### IAM 구성

- 구성 요소: 역할 / 정책 / 사용자 / 사용자 그룹
- 보안 → 자격 증명 경로에서 관리한다.
- **액세스 키는 함부로 만들지 말 것.**
- 사용자 생성 흐름: IAM → 사용자 → 콘솔 액세스 관리(콘솔 암호, 로그인 링크) 설정.
- 각 사용자마다 권한을 **타이트하게** 줘야 전체 서비스에 문제가 없다.

## 4. AWS 스타트업/개인 크레딧

- **개인사업자**: '혁신의 숲'을 통해, 회사 도메인·사이트·회사 이메일 계정이 있으면 국내 바우처로 추천받아 사용할 수 있다.
- **개인**: Amazon Lightsail — 유휴 서버를 빌리는 방식이라, 원래 주인이 쓰기 시작하면 바로 사라진다.
- 30만원 이하는 법적 처벌 없이 넘어가 주므로, 정 급하면 시도해 볼 방법 정도로 참고.
- AWS 서밋 같은 행사에서 경품으로 크레딧을 주기도 한다.
- 대학교 지원으로 저렴하게 쓰는 방법도 있다.
- 실무에서는 EC2 개발용 IAM 계정을 만들고, 백엔드 담당자가 있다면 JD로 지시하는 식으로 진행한다.
