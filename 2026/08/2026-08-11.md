# 2026-08-11 TIL — ROS2 노드·터틀봇 시뮬레이션과 프로젝트 설명법

## 1. ROS2 노드 기초

- **URDF**: 로봇의 구조를 기술하며, ROS의 **TF2** 좌표 변환을 쉽게 계산할 수 있게 해준다.
- **DDS**: 노드 간 통신을 담당하는 미들웨어.

## 2. 터틀봇3 시뮬레이션

터틀봇 실행을 위해 추가로 설치하는 도구들 (참고: ROBOTIS 터틀봇3 PC Setup 가이드):

| 도구 | 역할 |
| --- | --- |
| Gazebo | 시뮬레이션(월드) |
| Cartographer | 매핑 시뮬레이션 |
| Navigation2 | 자율주행 시뮬레이션 |

**Tip**: 터틀봇3 예제에서는 Cartographer와 Navigation2를 **동시에 실행하지 않는다.** 같은 map 노드를 쓰기 때문에 오차·오류가 날 수 있다. 다른 노드를 쓰며 매핑 결과를 넘기는 방법 등 더 나은 방식이 있다(추후 확인).

## 3. 취업지원 세션 — 잘 설명하는 사람

- **소프트 스킬**: 성격·태도·대인관계, 커뮤니케이션, 문제 해결력, 창의력, 리더십.
- 발표·면접 단계가 있는 이유는, 취준생이 내세우는 것(수상 경력, 툴 역량, 수료, 경력)과 면접관이 궁금해하는 것이 다르기 때문이다.

**면접관이 실제로 궁금한 것**:

- 무엇을 만들었는가 — 어떤 프로젝트를, 어떤 기술로?
- 어떻게 문제를 해결했는가 — 왜 이 기술을 택했나, 다른 대안은 검토했나, 어떤 기준으로 결정했나?
- 예상 못 한 문제는 무엇이었고, 원인을 어떻게 찾았나?
- 함께 일할 사람인가 — 팀에서의 역할, 의견 충돌 시 해결법, 설명 능력.

## 4. 내 대표 프로젝트 뽐내기

- 좋은 경험을 **가지는 것**과 좋은 경험으로 **보이게 전달하는 것**은 다르다.
- 기술적 판단을 상대가 이해할 언어로 설명하자. (예: "Fine-tuning 대신 RAG를 택한 이유는?", "성능과 비용 사이에서 무엇을 택했나?") 로봇이라면 "왜 그 센서와 제어 방식을 택했나?" 같은 질문으로 바꿀 수 있다.
- 정리 틀: 기획/배경(핵심 메시지·목표·직무 키워드·주요 결과) → 참여 시기 → 팀 인원 → 배운 것 → 역할.

## 5. 30초 안에 논리적으로 말하기

- **두괄식**: 결론부터, 근거는 다음. (예: "데이터 전처리 오류가 원인이었고, 전처리 로직을 수정해 해결했습니다.")
- **STAR 구조**로 경험을 구조화:
  - **S**ituation(상황), **T**ask(과제·역할), **A**ction(행동), **R**esult(성과).
  - 예시: S-OCR 정확도가 낮음 / T-정확도 개선 / A-전처리 추가 / R-정확도 18% 향상.
- **협업 경험**은 팀 목표 → 나의 역할 → 나의 행동 → 팀에 미친 결과 순으로. 역할·기여도·갈등 해결을 담는다.

실제 면접 단골 질문: 왜 그 기술을 택했나, 다른 방법은 검토했나, 가장 어려웠던 문제는, 본인의 기여는, 다시 한다면 무엇을 다르게 할까.

## 6. 전달 방식 — 벽을 세우지 않기

- 전문 용어로 벽을 세우지 말자. 면접관 중 비전공자가 있을 수 있으니 하드 스킬도 풀어서 설명한다. "~툴을 썼다"가 아니라 "~툴로 ~을 했다"로.
- 비언어적 커뮤니케이션:
  - 목소리·속도 — pause는 실수가 아니라 발표 기술이다. 중요한 문장일수록 의도적으로 천천히.
  - 자세 — 불필요하게 몸을 흔들지 말고, 손을 숨기거나 과하게 움직이지 말고, 질문을 받으면 바로 답하지 말고 생각한 뒤 답한다.
  - 발표 전체를 외우지 말고 첫 문장·마지막 문장·STAR 구조만 정리한다.
- **TL;DR**: 생각을 구조화하고, 듣는 사람이 필요한 정보 위주로 전달하자.
