# 2026-08-13 TIL — ROS2 노드 생명주기·Composition·colcon과 기록 습관

---

## 1. Node의 Life cycle

- ROS2 노드는 생성부터 활성/비활성/종료까지 정해진 **생명주기(lifecycle)** 상태를 가진다. 상태 전이를 통해 노드를 체계적으로 초기화·구동·정리할 수 있다.

## 2. Node Composition (합성)

노드를 독립 프로세스로 띄울지, 한 프로세스에 합성할지 선택한다.

|  | 독립 프로세스(기본) | Composition(합성) |
| --- | --- | --- |
| 견고성 | 높음(하나 죽어도 격리) | 낮음(같이 죽음) |
| 통신 비용 | 복사·직렬화 | 메모리 공유(제로 카피) |
| 적합 | 대부분의 노드 | 대용량 데이터를 주고받는 노드 묶음 |

## 3. colcon — 워크스페이스 빌드

- 의존성 순서는 `package.xml`로 판단한다.
- `install/setup.bash`로 환경을 등록한다.
- 증분 빌드로 변경점만 다시 빌드한다.

## 4. 네임스페이스 — 같은 노드 여러 번 띄우기

- 같은 노드를 여러 개 실행할 때 **네임스페이스**로 토픽·노드 이름 충돌을 피한다.

## 5. Parameter를 YAML로 분리하기

- 파라미터를 YAML 파일로 빼두면 **재빌드 없이 값만 바꿔** 쓸 수 있다.

## 6. C++ 패키지의 CMakeLists 선언

- C++ 패키지는 `CMakeLists.txt`에 빌드 설정을 단계적으로 선언한다(의존성 찾기 → 실행 파일/라이브러리 정의 → 링크 → 설치).

## 7. 공부·기록 습관에 대한 메모

- **라떼(튜터) 조언 — 공부할 주제를 고르는 기준**: 재미있는가? 공부할 기술적 값어치가 있는가? 주어진 시간·예산 안에서 되는가? 이력서에 쓸 수 있는가?
- **기록 관리**: 코드는 GitHub에 올리고, 혼자 하는 프로젝트라도 **Issue**를 잘 활용하자.
- **해외 개발 커뮤니티**: Discord, GitHub Issues, Reddit. 질문할 때는 **환경·버전·시도한 것·에러 전문**을 함께 적는다.
- **개발 블로그**: 나만 보기용이라도 쓰고, 제목에 에러 문구를 그대로 넣으면 나중에 검색이 쉽다.
- **막혔을 때**: 에러 메시지를 끝까지 읽는다.
